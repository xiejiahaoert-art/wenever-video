# 案例：一条视频看懂 Git 与 GitHub

这次从八页图文笔记重构成无旁白动画。原图文以毕设、旧图和跨设备取回为例，视频的目标观众改成正在用 AI 做小工具、还没弄清版本管理的人。参考片通过积木、电量和四格黑板把差异演出来；本片沿用可复用指标和道具接镜的做法。

## 内容和动作

| 原片动画时间 | 主任务 | 人物与道具 |
| --- | --- | --- |
| 0–5.34 秒 | 同一个项目，Git 本地有第 5 版，GitHub 为何停在第 4 版？ | 05、04 同时显示，人物跑向远端，跳起后指缺的那一格 |
| 5.34–26.71 秒 | Git 是版本控制工具。保存文件和留下提交分别会改变什么 | 保存后工作区发生变化，提交历史保持第 4 版。人物沿提交卡找到第 2 版 |
| 26.71–43.40 秒 | 用裁图工具短例说明恢复选定旧文件和提交 | 取回旧裁切文件，新命名文件留在原处。将要提交的文件摆进暂存区，再出现第 5 格 |
| 43.40–54 秒 | GitHub 是在线托管 Git 仓库的平台 | 把远端画成可访问的仓库，从它连到共享、协作和换设备 |
| 54–70.50 秒 | 推送让远端更新，新电脑可从更新后的仓库克隆 | 复制第 5 格送到远端，本地格保留。克隆后对照同一个提交编号 |
| 70.50–84 秒 | 回收概念：Git 本地记版本，GitHub 在线托管 | 把两种用途摆回同一屏，用人物和跳跃的标记串起两边，最后留住片名 |

原演示在一次性本地仓库中验证了两件事：从第 2 次提交仅取回裁切文件，新增命名文件仍在；提交第 5 版后远端仍是第 4 版，显式推送后新克隆才得到第 5 版。真实项目中用该仓库实际生成的提交编号。Git 和 GitHub 可选用官方资料核对术语：[Pro Git](https://git-scm.com/book/en/v2/Getting-Started-About-Version-Control) · [GitHub Docs](https://docs.github.com/en/get-started/start-your-journey/what-is-github)。

## 迭代中发现的问题

- 半写实卡通关键帧加轻推镜，人物动作仍读起来像会动的图片。改成火柴人关节和手部目标，几次取件、摆放、跳起和落地让动作改变物件状态。
- 用「提交通过」做字幕，初学者跟不上对象。在修复段展示杯子恢复完整，在提交段直接写选文件和留版本，将裁坏封面控制在引例。
- 原参考是 1080×1920，观感紧凑靠构图和互动。试过 4:5，按用户选择改回 9:16。重排人物和道具，同画布内继续让手够到文件和远端缺口。
- 用户回传的配乐文件共有 132 秒。黑段从约 83.83 秒开始，约 48 秒一直播放音乐。按约 112.9 BPM 的估算网格，对齐了落地、旧文件返回、第 5 版入格和片名。保留输入原音，压缩过渡并给片尾读字留半拍，最终剪到约 87.37 秒。末尾仍看得见片名，黑段检测通过。

## 发布字段示例

**标题**　Git 有第 5 版，GitHub 为什么只有第 4 版？

**话题**　#Vibe知识大赏 #Git #GitHub #版本控制 #AI编程 #编程入门

**配文**　点了保存，为什么 Git 的提交记录没变？明明提交了，为什么换台电脑打开 GitHub，看到的还是旧版？

这条视频用一个「本地第 5 版，远端第 4 版」的例子，讲清 Git 和 GitHub 分别做什么，以及保存、提交、推送三个动作的区别。下次让 AI 改项目之前，先用 Git 提交一个能跑的版本。


## 故事重做版

开场改成「代码改坏了。昨天那版，还能回来吗？」。同一计时器先正常、后报错。夜间工作桌上有伸手试运行、后仰、挠头的不同反应；报错用短特写，昨天用同形表盘接短闪回，再拉远成项目历史。约第 12 秒单独提出**版本控制**，之后才介绍 Git 和 GitHub。第一次进入 GitHub 时换成另一台电脑和在线仓库，最后让同样的计时器在新电脑重启。这个方案让例子继续回答开场问题。

字幕用一句可读的主判断，局部状态直接写到对应控件边上。片里删去提交哈希和命令标签，Git、GitHub 这两个核心名词保留。人物和标签有各自的活动区。图层抽检发现一个功能标签进了人物路径后挪到界面上沿，再检查挠头、取旧文件、推送和新电脑复现四处接触帧。相关研究和改法见 [表演、剪辑与教学画面的依据](research.md)。
